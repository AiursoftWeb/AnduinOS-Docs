# AnduinOS 2.0.5 Release Notes

AnduinOS 2.0.5 improves installation, desktop customization, and everyday reliability. Highlights include a new GNOME appearance profile, Fluent styling on the unlock screen, shrinking existing ext4 partitions, and keyboard selection before Wi-Fi setup. It also fixes Firewall startup without a translation, misleading Secure Boot status, and several interface layout problems. This release note remains a draft pending full ISO acceptance testing.

Live-media and installer changes require newly built 2.0.5 or newer installation media. Existing AnduinOS 2 installations can receive applicable package updates through APT; updating an installed system does not rewrite an older USB installer.

## New Features

* **Optional Factory Snapshot-History Deletion:** Factory Reset adds **Delete all snapshot history**, which also restores Home to its initial state. After System and Home recovery is confirmed, it deletes managed non-factory snapshots, including pinned and safety snapshots, and cleans up replaced subvolumes. Both New OS factory recovery points remain available for future resets. Interrupted cleanup retries without reporting completion prematurely. This option does not securely erase disks or clear data outside the managed System/Home recovery scope. See [Factory reset](../Applications/System/Disk-Snapshots-Manager/Disk-Snapshots-Manager.md#factory-reset).

* **GNOME Appearance Profile:** AnduinOS Appearance adds **GNOME** alongside **Classic**, **Separated**, and **Centered**. Selecting GNOME disables Dash to Panel, ArcMenu, and Blur my Shell to restore GNOME's standard panel and overview; selecting an AnduinOS layout configures its settings and enables those three extensions again. Unrelated extensions and theme settings are preserved. Taskbar position and behavior controls are unavailable in GNOME mode. Switching between GNOME and an AnduinOS layout shows a progress window while the extensions change, with guidance if the transition fails. Switching between already-enabled AnduinOS layouts remains a lightweight settings change.
* **Shrink Existing ext4 Partitions:** Advanced manual partitioning can now shrink a supported, unmounted ext4 partition to make room for another installation, alongside the existing plain-NTFS shrink support. Choose **Change Size**, select a size within the checked range, and acknowledge the backup warning. The proposed resize remains a plan until installation is confirmed and can be removed with **Undo Planned Resize**. The installer checks the filesystem before and after shrinking it, then shortens the partition without moving its start. This first version supports ordinary ext4 filesystems with 4 KiB blocks and an internal journal; Btrfs shrinking, encrypted volumes, LVM/RAID, and mounted, unclean, or unsupported ext4 filesystems are not supported. Back up important data before resizing.
* **Console Compatibility Startup:** The Live boot menu adds **Advanced Options... → Try or Install AnduinOS (Console Compatibility)** below **Safe Graphics**. It selects the on-screen kernel console with `console=tty0` while retaining normal graphics initialization and attempting to start the graphical Live desktop. This provides a workaround for certain splash-screen freezes or `plymouthd` crashes, verified on an ARM64 NVIDIA DGX Spark. The affected device range and frequency remain unknown. Ordinary startup and Safe Graphics retain their existing behavior; this option does not claim to fix every startup freeze. See [Installation diagnostics](../Install/Installation-Diagnostics.md#plymouth-startup).
* **Skip Media Check Startup:** A third advanced startup choice, **Try or Install AnduinOS (Skip Media Check)**, enters the Live environment without running the startup media check. It appears below **Console Compatibility** and uses ordinary graphical startup. Installation still verifies its source medium before changing partitions and blocks installation if verification fails. See [skipping the startup check](../Install/Installation-Diagnostics.md#skip-media-check).

## Behavior Changes

* **Confirmed AnduinOS EFI Replacement:** Reusing an EFI System Partition that already contains `EFI/AnduinOS` is no longer unconditionally blocked. The installer explains that replacing these boot files can prevent the previous installation from starting through that ESP and requires explicit confirmation. It verifies a backup before replacement and saves recovery files under `/var/backups/anduinos-installer/` in the new installation. Other EFI directories are preserved; this is a boot-file backup, not a whole-system rollback. Use a separate ESP when both AnduinOS installations need independent boot files. This replaces the stricter behavior introduced in 2.0.4 and addresses [installer feedback #28](https://github.com/AiursoftWeb/AnduinOS-2/issues/28).
* **Explicit Startup Verification:** The startup checker runs only when the kernel command line includes `rd.anduinos.media-check=1`. Ordinary language entries, Safe Graphics, Console Compatibility, and AnduinOS To Go explicitly include this parameter, so they continue checking media by default. The Skip Media Check entry omits it. An absent parameter or a value other than `1` skips the startup check and records the result as skipped, not passed. This does not change the installer's required verification.
* **Upstream Blur my Shell Packaging:** Blur my Shell continues using the shared resolver to select the newest upstream extension compatible with each target GNOME version. The local Dash to Panel blur-geometry patch has been removed because our fix was merged upstream in [Blur my Shell PR #907](https://github.com/aunetx/blur-my-shell/pull/907).

## Bug Fixes

* **Fluent Unlock Screen:** The session now includes a dedicated unlock-only theme extension that reuses the selected Fluent Shell theme, including its light, dark, and accent variants. This addresses the stock-looking unlock screen reported after suspend in [AnduinOS-2 #26](https://github.com/AiursoftWeb/AnduinOS-2/issues/26). A readability overlay improves the username and password prompt over bright wallpapers. High contrast, missing or non-Fluent themes, disabled User Themes, and theme-loading failures retain the native unlock appearance. Authentication and GDM resources are unchanged. The extension is enabled in the defaults after logging in again; existing accounts with customized extension lists retain their choices and can enable `unlock-theme@anduinos.com` explicitly after relogin.
* **Appearance Extension Switches:** Panel Widgets now reads effective GSettings values, including system defaults, rather than only explicit dconf overrides. A fresh Live session therefore correctly shows Desktop Icons as enabled when its icons are visible. Switches also update when extension settings change outside Appearance or are reset to their defaults.
* **Firewall Without a Translation:** Firewall no longer aborts when the current language has no translation catalog, such as Croatian, fixing [AnduinOS-Packages #15](https://github.com/AiursoftWeb/AnduinOS-Packages/issues/15). Failed translation initialization falls back to the original English strings instead of panicking.
* **Secure Boot Readiness:** Driver Center and the shared Secure Boot page distinguish **AnduinOS is ready, but Secure Boot is disabled** from a configuration that still needs repair. Enrolled certificates and trusted drivers no longer produce a misleading preparation warning merely because firmware enforcement is off. Setup Mode has separate guidance for configuring firmware platform keys, rather than treating it as another MOK enrollment problem. Unknown or unsupported firmware states remain explicit, and unsigned modules or broken automatic DKMS signing still require attention.
* **Secure Boot Actions on Trusted Systems:** Removed the redundant **Prepare AnduinOS for Secure Boot** button when Secure Boot is already active and enrollment is complete, even if the bootloader cannot be positively identified as shim. The conservative boot-chain preparation check remains in place before enabling Secure Boot; genuine enrollment and signing problems still expose the relevant repair actions.
* **Welcome Center Page Boundaries:** Fixed neighboring setup pages showing through at the left or right of the current page, particularly when a page contained little content. Each carousel page now fills its viewport while keeping its content width constrained, including the final **All Set** page and backward navigation.
* **Rounded List and Card Edges:** The installer's timezone list now clips selected rows and scrollbars to its rounded boundary. Swap Control's recommendation and stress-test warning cards likewise keep their colored accents inside the rounded edges.
* **Keyboard Layout Throughout Installation:** Keyboard selection now comes before Wi-Fi setup, so network passwords can be entered with the correct layout. Selecting a layout and variant applies them to the actual Live desktop session. The keyboard test field and subsequent username and password fields therefore use the selected layout rather than merely displaying its name. Testing and continuing are enabled only after the layout becomes active; failures offer a retry. Returning to change the installer language preserves a keyboard choice already confirmed by the user. The Live session keeps that layout after leaving the installer. This addresses [keyboard and Wi-Fi setup issue (AnduinOS-2 #27)](https://github.com/AiursoftWeb/AnduinOS-2/issues/27).
* **Installation Completion Instructions:** Removed duplicate MOK enrollment instructions from the completion message, also reported in [AnduinOS-2 #28](https://github.com/AiursoftWeb/AnduinOS-2/issues/28). Secure Boot installations retain their dedicated enrollment notice.
* **Menu Appearance After Updates and Reset:** AnduinOS now explicitly disables Blur my Shell's popup blur by default, preserving Fluent backgrounds and corners in the start menu and Quick Settings. This fixes unexpected transparency and rectangular blur edges introduced by newer extension defaults, including their return after resetting desktop appearance. Taskbar and overview blur settings are retained. Users can still enable popup blur themselves; resetting desktop appearance returns it to the AnduinOS default.

## Documentation

* **Installation Diagnostics FAQ:** A new [installation diagnostics guide](../Install/Installation-Diagnostics.md) covers Live black screens, Plymouth startup failures, media verification, Secure Boot detection errors, driver dependency conflicts, disk selection, and first-boot problems. Its media-check guidance complements the earlier [Live USB troubleshooting discussion #452](https://github.com/Anduin2017/AnduinOS/discussions/452); the automatic media check itself was introduced in 2.0.4, not this release. The guide also includes a manual `console=tty0` workaround for older installation images and explains which startup options are available from 2.0.5.
