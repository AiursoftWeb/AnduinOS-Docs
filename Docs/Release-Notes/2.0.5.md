# AnduinOS 2.0.5 Release Notes

Released on October 25, 2026, AnduinOS 2.0.5 brings optional coding-agent setup, a locally signed bootloader with guided Secure Boot recovery, Chinese Shuangpin input, and a more consistent Fluent desktop. It remains on the Ubuntu 26.04 LTS base and is available for AMD64 and ARM64.

These changes are relative to 2.0.4. Existing installations receive applicable package updates through APT. Installer and Live USB improvements require new installation media; updating the installed system does not update an existing USB image.

## Coding agents and Chinese input

Welcome Center adds **Control Your Computer with Natural Language**, an optional page for installing coding assistants. The international selection includes OpenCode, Claude Code, Codex, GitHub Copilot, Antigravity, and Grok Build. The Simplified Chinese selection includes DeepSeek Harness, Qwen Code, OpenCode with GLM, Kimi Code, MiniMax Code, and CodeBuddy Code.

Each installation presents the provider's notices before proceeding, shows progress and diagnostic details, and creates a branded application-menu shortcut. The page can be skipped. Provider accounts, credentials, service charges, and third-party terms remain separate from AnduinOS. See [Welcome Center](../Applications/System/Welcome-Center/Welcome-Center.md#control-your-computer-with-natural-language).

**Chinese (Rime)** adds Natural Code, Microsoft, and Xiaohe Shuangpin alongside full Pinyin. Focus a text field and press **F4** to choose a scheme. Welcome Center also introduces this shortcut in Simplified Chinese. See [Rime input](../Install/Use-Rime-Chinese-Input.md#switch-between-full-pinyin-and-shuangpin).

## Boot and Secure Boot

New AMD64 and ARM64 installations use AnduinOS-maintained GRUB, signed with a certificate created on the computer. The same certificate can sign third-party kernel modules. Shim retains Ubuntu's official EFI signature; the Live USB has its own official boot path so installation can begin before the local certificate exists. Offline installation includes the required payloads. Legacy BIOS support remains AMD64-only.

With Secure Boot enabled, the installer explains the required MOK enrollment before restarting. The certificate must be enrolled to start the new locally signed GRUB. It does not have to be enrolled again for each routine update that uses the same certificate.

When the installer creates a new EFI System Partition, it also deploys a direct fallback boot chain at the standard `EFI/BOOT` location. This gives compatible firmware another way to find the system if its normal AnduinOS boot entry is lost. It uses the same signed files, without the fallback registration program responsible for earlier reboot loops. Reused EFI partitions are not automatically given this fallback chain, protecting other systems' default boot files.

Driver Center now distinguishes firmware state, local certificate health and purpose, enrollment, driver trust, and bootloader readiness. Its recommended action follows the required order: prepare a certificate, finish enrollment, repair automatic signing if needed, then repair drivers or the bootloader. Explicit repair backs up damaged AnduinOS signing configuration; unrelated custom signing configuration remains protected. Results have localized summaries and expandable technical details. Disabling Secure Boot no longer makes an otherwise prepared system appear unprepared, and firmware Setup Mode receives separate guidance.

**Existing users are not automatically migrated from a working Ubuntu bootloader.** Ordinary updates retain that boot stack and existing certificates. Optional migration is a separate Driver Center operation. See the [boot-stack and signing guide](../Install/Secure-Boot-Signing-Architecture.md).

## Desktop appearance

* **Fluent on the lock and unlock screens:** The selected Fluent theme, including light, dark, and accent variants, now carries into the locked session and its menus. The unlock layout retains a spacious avatar and password prompt; text and notification cards remain legible over bright backgrounds. Notification text no longer receives inappropriate badge styling. Native appearance remains available when the selected theme is unsupported or high contrast is in use.
* **Existing extension preferences are preserved:** New sessions use the unlock extension by default. Accounts with a customized extension list may need to enable `unlock-theme@anduinos.com` after signing in again.
* **GNOME appearance profile:** Appearance adds a GNOME layout that restores the standard panel and overview. Switching back to an AnduinOS layout restores its taskbar and menu extensions. Other extension preferences and theme settings are preserved.
* **Menu and window fixes:** Default popup blur is disabled to preserve Fluent menu backgrounds and corners. Tiling Assistant is updated to fix state restoration after unlocking. Hidden Dash refresh errors are corrected, and Appearance switches now reflect system defaults and changes made outside the app.

## Installation and recovery

* **ext4 shrinking:** Manual partitioning can shrink a supported, unmounted ext4 partition to make room for another installation. The plan is applied only after installation is confirmed. This supports ordinary ext4 filesystems with 4 KiB blocks and an internal journal, not encrypted volumes, LVM/RAID, or Btrfs shrinking. Back up data before resizing.
* **Keyboard before Wi-Fi:** Keyboard selection now precedes network setup and applies to the Live session, including password and account fields. The installer waits for the layout to become active and preserves a confirmed choice when the language is changed.
* **External disks and existing EFI files:** Fixed whole-disk installation failing on external UEFI drives. Replacing an existing `EFI/AnduinOS` directory now requires an explicit warning and creates a backup. This does not make overwriting another installation's boot files harmless.
* **Readable installer pages:** Long disk identifiers wrap without hiding the Install button. Completion-page navigation and MOK instructions remain reachable, without duplicate enrollment instructions.
* **Factory reset with history removal:** An optional **Delete all snapshot history** action also resets Home and removes managed non-factory snapshots, including pinned and safety snapshots. Factory recovery points are retained. This is not secure disk erasure and does not remove data outside the managed System/Home scope.
* **Live rescue:** Offline boot repair verifies and regenerates the signed GRUB chain. Snapshot recovery preserves the damaged root rather than requiring a repaired bootloader before a snapshot can be restored. This is the Live USB Rescue Center, not the independent on-disk recovery environment being developed for a later release.

## Software sources, hardware, and everyday fixes

* **Flathub mirrors:** Control Panel adds automatic mirror selection, download-speed comparisons, and advanced selection of a supplied or custom Flathub address. Switching preserves installed applications and signing keys, without changing unrelated or per-user remotes.
* **Hardware updates:** Updated ALSA audio-routing profiles and SOF firmware are included. The optional Xbox controller driver package also receives an upstream refresh; it is not preinstalled in the ISO.
* **Voice Typing:** The optional voice-input software retains a usable backend selection across restarts and configuration changes instead of repeatedly benchmarking. Explicit retesting remains available.
* **VMware:** Both architecture images include desktop guest integration. Installation retains it for VMware guests and removes it on other machines.
* **Application reliability:** Fixed Driver Center becoming blank after a hardware scan, Firewall failing to start when a translation is unavailable, and YubiKey Security Center misidentifying an empty SSH agent as unavailable. Customize IBus no longer replays stale restart requests or displays their timestamps as dates such as 1970. Welcome Center pages no longer show portions of adjacent pages.

## Live USB startup

Persistent To Go startup avoids a redundant GPT partition-table reread that could fail while the USB was in use. The advanced menu adds **Console Compatibility** for certain graphical-startup problems and **Skip Media Check** for diagnosis. Skipping the startup check does not bypass the installer's media verification before disk changes. See [Installation diagnostics](../Install/Installation-Diagnostics.md).

## Upgrade guidance

AnduinOS 2.0 package updates stay on the Resolute base. Do not change Ubuntu suites or use `do-release-upgrade` as a substitute for a supported AnduinOS migration procedure. Disk-encryption installation, TPM automatic unlocking, and an independent recovery partition are not introduced by this release.
