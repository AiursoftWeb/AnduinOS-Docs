# AnduinOS 2.1.0 Release Notes

AnduinOS 2.1.0 moves to Ubuntu 26.10 (Stonking) and GNOME 51, with an adapted desktop, login theme, and application set. It also includes the community-edition improvements in 2.0.6: application-icon choices, optional Parakeet Voice Typing, mainland China software-source choices, and installation, driver, and snapshot fixes. These release notes are a draft.

Live-media and installer changes require newly built 2.1.0 installation media. A normal APT update on AnduinOS 2.0 does not migrate the system to 2.1.0. Do not change APT suites or use `do-release-upgrade`; an in-place migration requires a separately supported upgrade procedure.

## New Features


* **Ubuntu 26.10 and GNOME 51:** The new base includes Linux 7.3, GNOME Shell and GDM 51, systemd 261, APT 3.3, OpenSSL 4, and D-Bus Broker. The Fluent login theme and bundled extensions are adapted to GNOME 51, including its updated authentication controls. Third-party GNOME 50 extensions may require updates.

* **Impression USB Image Writer:** Impression replaces Startup Disk Creator as the preinstalled application for writing installation images to USB drives.

* **Mainland China Software Sources (Mainland China Users Only):** Simplified Chinese users can choose mainland China software servers during installation and first-run setup. The choice covers AnduinOS packages and the USTC Flathub mirror; it does not replace the separate Ubuntu mirror selector. Global sources remain the default. Each source is checked before switching, and a failed availability check leaves that source's existing configuration in place. First-run setup applies the requested changes immediately and reports failures.

* **Application Icon Choice:** AnduinOS Appearance adds **AnduinOS / App Defaults** under **Application Icons**, letting users switch between the Fluent icon theme and Adwaita without a terminal. The choice survives accent-color changes and later sessions. This addresses [the request to disable custom application icons (AnduinOS-2 #41)](https://github.com/AiursoftWeb/AnduinOS-2/issues/41).

* **Optional Parakeet Voice Typing:** Voice Typing adds **Parakeet TDT 0.6B v3 INT8** alongside Whisper Tiny, Base, and Small. It supports 25 European languages and local CPU recognition. The optional model needs about 631 MB to download, 812 MB for its installed weights, and approximately 1.5 GiB of working memory. Downloading requires confirmation and does not activate it automatically; choose **Use** afterward. Whisper Base remains the default, and the language list follows the selected model. Parakeet does not support every Whisper language. This follows the [dictation feedback and measured comparison in discussion #480](https://github.com/Anduin2017/AnduinOS/discussions/480#discussioncomment-19568463).

* **Optional Top Window Layout Menu:** Appearance adds **Show Top Window Layout Menu** for the layout choices displayed while dragging a window to the top of the screen. It is off by default and can be enabled without disabling ordinary edge snapping. See [Shortcuts and Appearance](../Install/Shortcuts-and-Appearance.md).

* **First-Run Rating and Feedback:** Welcome Center's final page offers an optional five-star rating and a short improvement comment for lower ratings. Submission is explicit, does not require an account, and reports network or rate-limit errors. Finishing setup does not require sending feedback.

* **Compound Bash Suggestions:** Command prediction handles empty commands after `sudo` and shell operators. After `apt update && sudo `, it can suggest `apt upgrade` and reuse preferred flags from matching history. Accepting a suggestion inserts text; it does not execute it.

## Behavior Changes


* **Desktop Icons on GNOME 51:** New AnduinOS 2.1 installations use the GTK 4 edition of Desktop Icons NG (currently DING 103). AnduinOS 2.0 keeps GTK 3 as its default, and ordinary package upgrades preserve the edition already installed. Explicitly installing the alternative package and logging out and back in switches editions. See the [multi-monitor discussion #430](https://github.com/Anduin2017/AnduinOS/discussions/430) for the original reports and hardware-coverage limits; this release does not claim that every multi-monitor issue is fixed.

* **File Preview:** Sushi's Space-key file preview is no longer preinstalled.

* **Restart After Snapshot Restore:** Desktop System, Home, and factory restores now restart after applying disk changes, then boot the restored system normally. This lets the restored system use its own kernel and matching modules after an update. Startup confirmation and automatic fallback distinguish the restore boot from the subsequent normal boot. The temporary boot entry is named **Start snapshot rollback (one-time)**. Compatibility checks can reject desktop restores from older snapshots that do not support the required boot protocol. See [Disk Snapshots Manager](../Applications/System/Disk-Snapshots-Manager/Disk-Snapshots-Manager.md).

* **Printer Management Through GNOME Settings:** Driver Center lists configured printers and provides a direct route to GNOME's printer settings, refreshing its status when users return. Its wording distinguishes installed printing support from a printer that has actually been configured. See [printing and scanning](../Applications/System/Driver-Center/Driver-Center.md#printing-and-scanning).

* **Clearer Graphics Status:** Driver Center's sidebar identifies the graphics category more clearly. Intel graphics already using the native `i915` or `xe` kernel driver can show a ready state without suggesting that another driver needs to be installed.

* **Package and System Versions:** Shared AnduinOS applications can use a `2.1.0-*` package version on the 2.0 release line. The package version does not change the installed Ubuntu base or mean that the computer has migrated to AnduinOS 2.1. System identity remains specific to its release line.

## Bug Fixes


* **GTK Appearance After Locking:** The theme extension no longer temporarily resets shared GTK theme settings when the screen locks. This addresses a reproduced cause of applications returning with light window decorations despite dark mode. The [original Firefox and Thunderbird report (AnduinOS-2 #37)](https://github.com/AiursoftWeb/AnduinOS-2/issues/37) remains useful for the remaining application-specific verification; this change does not claim that every reported Thunderbird or context-menu variant is resolved.

* **On-Screen Keyboard Above Start Menu:** Backported the [ArcMenu stacking fix](https://gitlab.com/arcmenu/ArcMenu/-/merge_requests/287) that keeps the on-screen keyboard above an open menu, allowing its keys to remain reachable while typing in the menu.

* **Firmware Updates With Secure Boot:** The AnduinOS shim package now exposes Ubuntu's officially signed shim through fwupd's supported lookup path. This addresses firmware preparation reporting that shim is missing after switching to the AnduinOS boot stack, including [the Dell firmware-update report (AnduinOS-2 #39)](https://github.com/AiursoftWeb/AnduinOS-2/issues/39). It does not overwrite another operating system's EFI directory or guarantee that a particular device has an available firmware update.

* **Final Bootloader Preparation During Installation:** The installer prepares and verifies the current signed GRUB payload after optional package updates. Previously, an online update could replace GRUB after its signature had been prepared, leaving the first installed boot with a stale deployment status. The existing machine certificate is reused.

* **Installer Mirror Fallback:** Failed signed-index refreshes and attributable Ubuntu mirror download failures can advance to another mirror. Language packs, input methods, and multimedia packages now use this download fallback too. A new mirror must pass signed-index verification; package-configuration failures and unrelated errors are not blindly retried.

* **Repeated Automatic Snapshots:** Boot-time and calendar timers firing within seconds of each other now produce a normal duplicate-request skip instead of marking the automatic snapshot service failed. Manual snapshot rate limits, storage errors, and retention cleanup remain effective.

* **Home Restore Boot Loop:** Home rollback no longer repeatedly selects the temporary restore entry after completion. The new restore protocol uses the entry once, and normal Linux entries remain ahead of it in the default boot order.

* **Live Rescue Workspace Cleanup:** Rescue Center waits for its emergency terminal and recovery mounts to finish closing. The installer refuses to start disk changes while a rescue workspace is still active, explains how to close it, and allows installation to be retried afterward.

* **Live Btrfs Restore With System Storage Subvolumes:** Rescue Center can restore a system containing the empty `var/lib/machines` and `var/lib/portables` subvolumes created by systemd. It previously rejected that layout as unsupported. Non-empty storage subvolumes and unknown nested subvolumes remain protected rather than being deleted.

* **Live Media Verification Tools:** The Live initramfs includes the full `realpath` implementation required by the media verifier, avoiding failures when an earlier BusyBox tool lacks the options needed to validate source paths.

* **GTK 3 Desktop-Icon Focus:** The retained GTK 3 DING extension waits until a window is mapped before activating it, avoiding a reproduced Mutter stacking assertion during focus changes. This is separate from the GTK 4 desktop-icon selection on Stonking.

* **Firewall Diagnostics:** Firewall now warns about firewalld, independently configured nftables, and persistent iptables rules that may still filter traffic while UFW is off. It distinguishes installed software from running services and detected rules, and explains missing UFW or incomplete checks. Audit results say **No Reply Observed** instead of treating an absent reply as proof of blocking. These changes follow [the Samba investigation (AnduinOS-2 #40)](https://github.com/AiursoftWeb/AnduinOS-2/issues/40); the application does not automatically remove another firewall or change its rules.

* **Driver Center on Narrow Windows:** Fixed sidebar and content overflow so driver information and navigation remain accessible when the window collapses to a narrower layout.

* **DKMS During Upgrades:** Driver build commands remain available throughout package replacement, avoiding failures caused by a temporarily missing DKMS frontend. Cleanup failures are reported rather than silently ignored.

* **Xbox Driver Upgrades:** The optional xpadneo driver rebuilds for each installed kernel with the required headers, and upgrade handling avoids leaving a removed driver revision registered without its sources. This follows [the kernel-update report (AnduinOS-2 #38)](https://github.com/AiursoftWeb/AnduinOS-2/issues/38). Already-stale DKMS registrations may still require separate cleanup; a successful new module build does not repair every old registration.

* **Input-Source Preferences:** Signing in no longer adds Japanese Mozc back after the user removes it from the input-source list.

* **Taskbar Auto-Hide:** Fixed pointer reveal after a rejected auto-hide activation, allowing the panel to appear again when the pointer reaches the screen edge.

* **Start-Menu Translations:** Corrected initialization of translated power-action labels instead of retaining labels translated before the locale was ready.

* **First-Session Flatpak Applications:** Flatpak D-Bus service directories are prepared before the first login, avoiding missing-directory errors during session startup. This is a specific integration fix, not a claim that all Flatpak launch problems are resolved.

* **System Branding and Privacy Link:** GNOME's system identity uses AnduinOS artwork and links to the AnduinOS privacy statement. The logo asset is owned by the base-files package so it remains available independently of other desktop packages.

* **Clearer French Diagnostics:** Replaced misleading French labels such as **Sortie avancée** with **Détails techniques** and harmonized related installation, configuration, and repair messages. This addresses the [translation feedback in discussion #480](https://github.com/Anduin2017/AnduinOS/discussions/480#discussioncomment-19557733).

* **Parental-Control Service Dependencies:** The desktop metapackage now pulls in Malcontent's core service dependencies, resolving the earlier missing-service-account activation errors. This does not enable parental restrictions or install the complete parental-control interface. The separate timing defect remains listed below.

* **GNOME 51 Login Controls:** Adapted Fluent styling for the new password-submit button and authentication-option controls so the login screen retains its intended layout.

* **Official GDM Crash Fix:** New media include Ubuntu's GDM `51.0-0ubuntu1.1` update, which fixes a double-free when the Ubuntu session is not installed. This resolves the login-manager crash seen in early Stonking candidates; the fix comes from Ubuntu rather than an AnduinOS-specific GDM fork. See [the official package changelog](https://changelogs.ubuntu.com/changelogs/pool/main/g/gdm3/gdm3_51.0-0ubuntu1.1/changelog).

* **Graphical Startup:** Early VirtIO display support and graphical-console settings improve Plymouth startup with the new boot stack. This targets the virtual display path rather than promising a fix for every physical graphics device.

* **Stonking Input-Method Packages:** The installer recognizes Stonking's Rime engine layout and verifies the matching input-method payload, avoiding rejection based on the older directory arrangement.

## Documentation and Packaging


* **Bundled License Notices:** Expanded or corrected upstream and dependency notices for firmware, themes, extensions, controller drivers, and native system tools. Large Rust and speech-tool notice files are compressed on disk while retaining their contents.

* **Public Source References:** Package metadata and documentation use public GitHub source links so users can inspect the implementation without access to the internal development service.

## Known Issues

* **Chinese Input:** An upstream IBus object-reference issue can produce GNOME Shell assertion messages when using Chinese input. Text input worked in the tests that recorded these messages.
* **Location Service:** GeoClue can time out during startup because of an upstream GLib deadlock, affecting applications that request location information.
* **Parental Controls:** An upstream Malcontent timing issue can produce assertion messages in the system log, including on systems where screen-time limits are not enabled. The service remained running during testing.
* **Disk Service Startup:** An upstream UDisks2 initialization race can produce a warning during startup. The race was reproduced under controlled diagnostic conditions; testing has not established data loss or a reproducible failure during normal startup.
