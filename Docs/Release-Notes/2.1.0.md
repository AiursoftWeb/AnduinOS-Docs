# AnduinOS 2.1.0 Release Notes

!!! warning "Development draft — not a release announcement"

    AnduinOS 2.1.0 is still undergoing installation and desktop qualification. These notes describe the October 29 development candidate and reviewed changes, not a production release or a claim that all acceptance tests have passed. The final image contents and known issues must be checked again before publication.

AnduinOS 2.1.0 moves to Ubuntu 26.10 (Stonking) and GNOME 51. Compared with [2.0.5](2.0.5.md), it adds an independent recovery environment, updates the desktop and default USB-writing application, and improves input-source preferences, command suggestions, and driver maintenance. Features already introduced in 2.0.5 are retained rather than counted as new changes here.

## New Ubuntu and desktop base

The current AMD64 candidate includes Linux 7.3, GNOME Shell 51, GDM 51, systemd 261, APT 3.3, and OpenSSL 4. It also includes D-Bus Broker. These are changes from the Ubuntu 26.04-based 2.0 series; the final release's exact package versions remain subject to qualification.

The login theme is adapted to GNOME 51's password submission and authentication controls. The taskbar, start menu, and other bundled extensions have been updated for the new desktop. This does not guarantee that third-party extensions supporting GNOME 50 will work with GNOME 51.

**Impression** replaces Startup Disk Creator as the preinstalled USB-image writing application. Sushi's Space-key file preview is not preinstalled in this candidate. Snap remains absent from the default image.

## Independent recovery environment

A new **AnduinOS Recovery Environment** entry can start a separate kernel and recovery interface when the installed desktop cannot boot. It allows supported Btrfs system snapshots to be restored without a Live USB or network connection while preserving personal files.

The graphical browser lists recovery points and marks the checkpoint associated with the **Last successful boot**. That marker helps selection but does not guarantee that a snapshot will boot. **Snapshot Current State** can preserve the installed system before rollback when its required boot files and metadata remain readable. The interface warns when no current-state snapshot has been created. A System Information view supplies read-only diagnostic details, and failures have a separate details page. A text interface is available when graphical startup is unavailable; the recovery interface is currently English.

New supported, unencrypted Btrfs whole-disk installations create a dedicated recovery volume. Ordinary package upgrades do not repartition existing systems. Driver Center can inspect and repair recovery deployment. Its preparation action can create a 256 MiB recovery partition from an eligible ordinary GPT swap partition of at least 512 MiB on the system disk, then guide installation and boot-entry repair. It checks the disk layout and requires explicit confirmation; it does not silently repartition the machine during an update. Unsupported layouts do not offer this action. Ext4 roots and encrypted layouts do not gain this Btrfs recovery capability.

The recovery volume is hidden from ordinary desktop file browsing. Removing the recovery package removes its boot-menu entry but retains recovery data. Boot-success recording is restored when the package is reinstalled.

!!! warning "Recovery qualification is separate from normal Secure Boot"

    Normal-system Secure Boot support does not establish recovery-environment support. The recovery package remains under qualification, and boot-time authentication of its initramfs is not implemented. Do not rely on it as a fully authenticated recovery chain. Keep trusted installation media available.

## Desktop and driver improvements

* **Input-source choices stay yours:** Signing in no longer adds Japanese Mozc back after it has been removed from the input-source list.
* **Better Bash suggestions:** Command prediction handles empty commands after `sudo` and shell operators. After `apt update && sudo `, it can suggest `apt upgrade` and reuse preferred flags from matching history. Accepting a suggestion only inserts text; it does not execute it.
* **Taskbar auto-hide:** Fixed pointer reveal after a rejected auto-hide activation, so moving to the screen edge can reveal the panel again.
* **Start-menu translations:** Corrected initialization of translated power-action labels.
* **Privacy information:** System identity now points to the AnduinOS privacy statement rather than Ubuntu's privacy page.
* **First-session application integration:** Flatpak D-Bus service directories are prepared before the first login, avoiding missing-directory errors during session startup.
* **Driver maintenance:** Package upgrades keep DKMS callable throughout the transaction. The optional Xbox driver rebuilds for installed kernels that have the necessary headers rather than assuming that only one kernel needs a module. Graphics-driver status is also clearer in Driver Center navigation.
* **Graphical startup:** The candidate includes the desktop graphical-console policy and early VirtIO display support needed by the revised startup stack. These changes are still being qualified on the new images; they are not a promise to fix every hardware-specific blank screen.

## Known issues in the development candidate

* **Location service:** GeoClue can time out during startup because of the tracked GLib deadlock. No AnduinOS fix is deployed yet.
* **Malcontent service activation:** Incomplete upstream package splitting can leave D-Bus declarations referring to missing services or accounts. This is not resolved by silently installing parental-control features.
* **IBus diagnostics:** Object-reference handling defects remain in the Ubuntu packages under investigation. Upstream fixes exist, but their availability in an installable Ubuntu update has not yet been confirmed. AnduinOS has not shipped a local IBus backport.

These are the recorded findings as of October 29, not fresh confirmation of upstream publication. The current candidate also requires further Live startup and installation qualification. The login workaround included in the candidate does not resolve these other upstream issues.

## Installation and upgrade boundary

The current qualification target is a new 2.1.0 installation. A normal APT upgrade on AnduinOS 2.0 stays on Resolute; it does not migrate the machine to Stonking. Do not manually switch suites or run Ubuntu's distribution upgrader to obtain this candidate. A supported in-place migration, if offered, requires a separate procedure and validation.
