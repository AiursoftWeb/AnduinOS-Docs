# AnduinOS 2.0.4 Release Notes

AnduinOS 2.0.4 focuses on more reliable installation and recovery, clearer boot menus, and fixes found through testing on real computers and USB media. It redesigns the installation progress screen, adds a graphical Rescue Center to the Live environment, verifies installation media before disk changes, and introduces the optional HyperFluent GRUB theme. New installations also use the GTK 3 edition of Desktop Icons NG.

Live-media and installer changes require newly built installation media. Existing AnduinOS 2 installations can receive applicable package updates through APT; updating an installed system does not rewrite an older USB installer.

## New Features

* **Installer Help and About:** A localized help menu now provides a native About dialog and direct links to the project source, website, and issue tracker. Users can find the installer version and support links without leaving the installation workflow.
* **AnduinOS Rescue Center:** The Live desktop now includes a graphical tool for discovering installed AnduinOS systems and opening a dedicated recovery workspace. It provides password reset, file browsing, system details, and restoration of compatible Btrfs System snapshots even when the installed desktop will not start. A safety snapshot of the current System is enabled by default before restoration, while the separate Home subvolume is left untouched. This follows the [discussion about recovering snapshots when the installed system cannot boot](https://github.com/Anduin2017/AnduinOS/discussions/448). The interface and helper diagnostics are localized. The tool rechecks the selected device before modifying it and cannot repair the system it is currently running from. Encrypted filesystems and automated package repair remain outside this release.
* **Guided Boot Repair and Emergency Terminal:** Rescue Center can diagnose boot files and perform guided repair for supported offline UEFI installations, with live progress and expandable command output. Guided repair requires the selected installation's EFI partition to be on the same disk; BIOS, separate `/boot`, and cross-disk EFI configurations require manual diagnosis. An advanced emergency terminal is also available from the Live environment inside the selected offline system. It mounts the standard Btrfs Home subvolume at `/home`; on ext4, the normal Home directory is available through the mounted root filesystem. Custom separate Home partitions still require manual mounting. A successful repair still needs a real reboot to confirm that the machine starts.
* **Automatic Installation-Media Check:** Following [reports of a Live USB reaching an unexpected login screen](https://github.com/Anduin2017/AnduinOS/discussions/452), the Live boot checks the installation medium and reports progress or a recoverable error. The installer verifies its source image again as a privileged preflight step, before changing partitions; a failed or unavailable check blocks installation. Users can still enter the Live desktop to inspect a problematic medium. The separate GRUB menu item for checking media was removed because the normal boot path already performs the check.
* **HyperFluent GRUB Theme:** A new optional package provides an AnduinOS-branded boot menu for installed systems, and the Live ISO includes the same artwork. The theme retains menu icons, selection highlighting, and a slim blue frame across common 16:9 and 16:10 display modes. Existing systems can install or remove the theme independently; it does not change boot commands, kernels, or recovery entries.
* **Three Boot Display Choices:** Control Panel now distinguishes **High resolution (if available)**, **Automatic**, and **Large text mode**. High resolution tries a connected display's preferred mode and falls back to GRUB's automatic choice if firmware does not offer it. Automatic is the old, inaccurately named “Native resolution” behavior: GRUB and firmware choose the mode. Large text prefers lower resolutions for readability. A high-resolution menu may have smaller-looking text, especially on 4K screens; no choice guarantees the panel's native resolution during early boot.
* **Selectable Ubuntu Mirrors:** Control Panel's software-source page now lets users select an Ubuntu mirror in addition to switching automatically to a suitable mirror. Source errors are localized, and the automatic switch is presented as the primary action.
* **GTK 3 Desktop Icons for New Installations:** To address [reports of desktop icons jumping between monitors](https://github.com/Anduin2017/AnduinOS/discussions/430#discussioncomment-18664783), new installations roll back Desktop Icons NG from the GTK 4 implementation to the GTK 3-based v85 release through `gnome-shell-extension-desktop-icons-ng-gtk-3-anduinos`. The extension metapackage recommends GTK 3 first, with the regular GTK 4 package as an alternative, so existing GTK 4 users are not automatically switched when upgrading. Users can switch explicitly by installing either this GTK 3 package or `gnome-shell-extension-desktop-icons-ng-anduinos` for GTK 4; APT replaces the conflicting version. Log out and back in after switching. A separately installed user copy of DING must be removed or moved aside to use the system package. Multi-monitor reports remain under investigation; this change does not claim that every reported issue is resolved.

## Behavior Changes

* **Redesigned Installation Screen:** The installation page has been rebuilt around a full presentation view, with refreshed slideshow backgrounds, illustrations, and text. Slides advance automatically and can also be browsed with the previous/next controls. The current installation status and overall progress remain visible below the presentation. An **Output** button switches to a dedicated view containing the installation steps and live command logs. Installation failures open that view automatically; successful installations replace the slideshow with the completion result and restart action.
* **Native Installation-Log Saving:** **Save Log** now opens the desktop's native file chooser so users can choose where to save the installation output. Write failures are reported instead of silently losing the log. Logs remain available for diagnosing a failed installation.

* **More Predictable Live USB Boot:** The ISO uses a volume label that cannot collide with AnduinOS boot-parameter names when Rufus writes it in ISO mode. This fixes a case where Rufus could change the boot arguments, skip Live setup and media verification, and leave users at a login prompt. The ISO-mode regression tests cover default and custom USB labels; writing the image in DD mode remains supported.
* **Portable-Boot Guardrails:** The Live environment detects unsupported AnduinOS To Go media and explains why it cannot continue, instead of proceeding into a broken boot path.
* **Voice Typing Backend:** The offline Voice Typing service has moved to a Rust implementation while retaining the user-facing dictation workflow and its compatibility checks.
* **Secure Boot Preparation:** UEFI installation and driver setup use the signed shim/GRUB boot path and prepare required MOK enrollment before enabling Secure Boot. This reduces first-boot failures caused by an incomplete trust chain.
* **Independent Linux Boot Menus:** Coexistence installations can discover supported existing Linux EFI bootloaders and add entries that start their own boot menus. The installer also explains the differences between shared and separate EFI System Partitions before users choose an arrangement.
* **BIOS Startup Branding:** When BIOS boot has no firmware logo to display, the central Plymouth splash now uses the AIURSOFT symbol, with AnduinOS branding below it.

## Bug Fixes

* **Driver Installation After Kernel Changes:** The installer rechecks driver selection when platform packages introduce a different kernel, helping ensure that the matching NVIDIA modules are installed before the first reboot. It now checks package health even when the driver command reports success, and verifies NVIDIA modules against the generated default Linux boot entry.
* **Boot Image Updates During Package Installation:** Plymouth and snapshot-manager package updates now use Ubuntu's `update-initramfs` command and its deferred package triggers, allowing new kernels to finish configuration before boot images are generated. This fixes premature checks that could interrupt image builds or system upgrades, including the [Plymouth upgrade failure report](https://github.com/Anduin2017/AnduinOS/discussions/459). On systems using Dracut, that command is supplied by Ubuntu's dracut package. Final installation checks still reject missing or invalid boot images; the migration helper retains its fallback and post-reboot confirmation.
* **Firmware Detection:** Fixed installation being blocked when `mokutil` returned a nonzero status for firmware without Secure Boot support. Firmware probing now distinguishes a known unsupported state from an unknown or failed read, attempts supported recovery, and preserves diagnostic details. Successful detection now advances automatically instead of leaving an empty-looking completion page. The Secure Boot recommendation is skipped when Secure Boot is already enabled or unsupported; failed detection retains its diagnostics and retry action.
* **Installation on Small Displays:** Pages now hide their large colored banners when window height is limited and provide scrollable content while keeping navigation reachable. This allows users with displays such as 800×600 to continue through the installer. The installation steps, slideshow, and completion results also remain reachable in small windows; long restart-button text wraps rather than forcing the right column outside the window.
* **Keyboard Layout Search:** Fixed the layout and variant dropdowns showing a search field without filtering their lists. Variant searches apply to the currently selected keyboard layout.
* **Existing AnduinOS EFI Files:** Coexistence installation now rejects reuse of an EFI partition that already contains `EFI/AnduinOS`, directing users to a separate EFI partition instead of overwriting another AnduinOS installation's boot files.
* **Secure Boot Repair with Multiple EFI Partitions:** Repair validates the selected installation's mounted EFI partition and matching firmware entry, including supported chainloaded arrangements, instead of assuming that the first-stage bootloader identifies the target partition.
* **Live-System Package Upgrades:** Boot migration and GRUB refresh operations that apply to installed systems are skipped when upgrading the Live environment.
* **GRUB Layout on Real Displays:** Fixed boot-menu artwork being cropped, stretched, or misaligned on some firmware resolutions. The menu frame is drawn by GRUB rather than baked into the wallpaper, keeping its border aligned with the selection and menu entries. Menu icons and editor alignment were also corrected.
* **Offline Snapshot Restore:** Rescue Center now probes Btrfs installations correctly on current kernels, handles Live-session authorization, and waits for the retired System subvolume to be removed before declaring recovery complete.
* **Offline Btrfs Boot Repair:** Guided repair mounts the selected root subvolume directly so GRUB can resolve the filesystem containing `/boot/grub`.
* **Recovery Boot-Image Generation:** Guided boot repair rebuilds boot images only for installed kernels, using explicit `/boot/initrd.img-<version>` output paths. Leftover module directories from removed kernels no longer cause repair to regenerate obsolete images or guess an incorrect EFI output location.
* **Recovery File Export:** Rescue Center exports files through a private staging directory and refuses to overwrite an existing destination. Export handling also protects against destination-directory replacement while copying. The export destination must support Unix ownership and private directory permissions; for FAT/exFAT media, export to Home first and then copy the recovered files using Files.
* **Interrupted Offline Recovery:** Btrfs system discovery can identify the original root from the recovery journal if a restore was interrupted between root-subvolume renames, allowing the recovery workflow to recognize the installation again. Offline root inspection and file operations also reject paths that escape the selected system.
* **BIOS Live Boot Theme:** Fixed the Live ISO's BIOS boot path falling back to the wrong GRUB theme.
* **Desktop Extension Defaults:** Corrected ArcMenu defaults to match the packaged extension version and removed obsolete extension settings.
* **BitLocker Partition Safety:** Corrected manual-storage planning so an existing BitLocker partition is preserved when the user chooses to keep it, addressing the confirmed [installation blocker alongside Windows 11](https://github.com/AiursoftWeb/AnduinOS-2/issues/21).
* **Manual Root Size:** Manual partitioning now enforces a 6 GiB minimum for the root filesystem instead of accepting an installation target too small to use.
* **German Localization:** Replaced English fallback text in the factory-reset and recovery-point interfaces, including their warnings and confirmation actions, following the [Control Panel localization report](https://github.com/Anduin2017/AnduinOS/issues/447). Control Panel's software-source page now uses consistent German terminology for mirror servers and switching them, including the [additional translation corrections reported by users](https://github.com/AiursoftWeb/AnduinOS-2/issues/18#issuecomment-5764188556). Related software-source wording was corrected in other supported languages as well.
* **Home Backup Launcher:** Control Panel now opens an installed native Deja Dup directly, with the Flatpak version as an alternative, instead of unnecessarily opening the software store. This addresses the backup-launcher problem in the [2.0.3 feedback report](https://github.com/AiursoftWeb/AnduinOS-2/issues/18); other suggestions in that report are not all included in this release.
